# Conventions

How this repository is organised, and the rules every change follows.
Goal: logic is written **once**, layers stay thin, nothing is hardcoded, and no secret ever lands in git or state.

## 1. Root modules and child modules

```
eks-platform-infra/
├── modules/                    ← CHILD modules: all the logic, written once, reused
│   ├── s3_bucket_secure/       versioning, SSE, public-access block, optional lifecycle
│   ├── budget/                 monthly budget + actual/forecast email alerts
│   ├── github_oidc_role/       IAM role trusted only for one repo/branch/environment
│   ├── account_baseline/       region-wide guard rails (EBS encryption by default)
│   ├── permissions_boundary/   boundary every CI-created role must carry (ADR-0018)
│   ├── pod_identity_role/      IAM role for one Kubernetes service account (EKS Pod Identity)
│   ├── ecr_repository/         immutable tags, scan on push, lifecycle policy
│   ├── ssm_contract/           publishes a layer's outputs to SSM Parameter Store
│   ├── network/                wraps terraform-aws-modules/vpc + NAT instance + S3 gateway endpoint
│   ├── eks_cluster/            wraps terraform-aws-modules/eks + add-ons + Pod Identity
│   └── rds_postgres/           (Phase 1, 03_data)
├── live/                       ← ROOT modules: thin wiring, one state each, applied in order
│   ├── backend.hcl             bucket + region + lockfile, written once
│   ├── 00_bootstrap/           persistent
│   ├── 01_network/             daily
│   ├── 02_eks/                 daily
│   ├── 03_data/                daily
│   └── 04_vault/               daily
├── scripts/                    leftover-check.sh: same checks in the nightly destroy and on the laptop
├── .github/workflows/          plan (PRs) · apply (merge + approval, or Run workflow) · destroy (22:00 UTC)
├── .pre-commit-config.yaml
└── .tflint.hcl
```

**Root module (`live/NN_layer/`)**: answers *what* and *how much*. It contains only:
`module` calls, `data` lookups, `locals`, and values in `terraform.tfvars`.
**No `resource` blocks in roots.** If a root needs a resource, it belongs in a child module.

**Child module (`modules/<name>/`)**: answers *how*. It contains the resources and the safe defaults.
A child module must add value: it bundles several resources, enforces safe defaults, or gives a simpler interface.

**Community modules** (`terraform-aws-modules/vpc`, `terraform-aws-modules/eks`) are called **only inside our
child modules** (`network`, `eks_cluster`), never from a root. Roots keep a small, stable interface, and an upgrade of
a community module happens in one place.

To change behaviour, edit the child module once. To change a size or count, edit the root's `terraform.tfvars`.

## 2. Files: every root layer has the same set

| File | Contains | Never contains |
|---|---|---|
| `backend.tf` | `backend "s3" { key = "NN_layer/terraform.tfstate" }`, the key only | bucket, region |
| `versions.tf` | `required_version`, `required_providers` | |
| `providers.tf` | `provider` blocks with `default_tags` | credentials |
| `data.tf` | account, region, AZs, values from other layers (SSM) | |
| `locals.tf` | naming, computed values | |
| `main.tf` | `module` calls | `resource` blocks, literal names/IDs/ARNs |
| `variables.tf` | inputs with `description` + `type` (+ `validation`) | secrets |
| `terraform.tfvars` | the only place for tunable values (CIDRs, sizes, counts) | secrets |
| `outputs.tf` | outputs with `description` | |
| `README.md` | generated by terraform-docs | |

Child modules: `main.tf`, `variables.tf`, `outputs.tf`, `versions.tf`, `README.md`.
`versions.tf` declares `required_providers` only: **no `provider` block, no backend** in a child module.

Init a root with the shared backend file:
```bash
cd live/01_network
terraform init -backend-config=../backend.hcl
```

## 3. No hardcoding

| Instead of typing | Use |
|---|---|
| Account ID | `data.aws_caller_identity.current.account_id` |
| Region | `data.aws_region.current.region` |
| AZ names | `data.aws_availability_zones.available.names` |
| Resource names | `"${var.project}-<thing>"`, `project = "myeks"` (e.g. `myeks-alb`, `myeks-github-infra`) |
| Globally unique names (S3) | `"${var.name_prefix}-<thing>"`, `name_prefix = "ntnick-myeks"` (e.g. `ntnick-myeks-tfstate`) |
| Account-wide resources | named for what they watch, not the project (e.g. budget `account-monthly-cost`) |
| Every subnet CIDR | one VPC CIDR in tfvars → `cidrsubnet()` in the child module |
| Tags on every resource | `default_tags` (`Project`, `Layer`, `ManagedBy`) |
| Backend bucket/region | `live/backend.hcl`, once |
| Values from another layer | SSM contract (below) |
| Magic numbers in child modules | variables with sensible defaults |

### Linking layers: the SSM contract
Layers do **not** use `terraform_remote_state`: it repeats backend config in every consumer and needs read
access to the whole state file. Instead, a layer publishes what others need through the `ssm_contract` module:

```hcl
# live/01_network/main.tf: publish
module "contract" {
  source = "../../modules/ssm_contract"
  path   = "/${var.project}/network"
  values = {
    vpc_id             = module.network.vpc_id
    private_subnet_ids = join(",", module.network.private_subnet_ids)
  }
}

# live/02_eks/data.tf: consume
data "aws_ssm_parameter" "vpc_id" {
  name = "/${var.project}/network/vpc_id"
}
```
Parameter names are the interface between layers. CI scripts read the same values with `aws ssm get-parameter`.

Reference chain: a layer reads only from layers **above** it, never below.
```
00_bootstrap → /myeks/bootstrap/*   (ECR, KMS, ACM, Loki bucket)
01_network   → /myeks/network/*     (vpc_id, subnet ids)
02_eks       → /myeks/eks/*         reads network/*, bootstrap/*
03_data      → /myeks/data/*        reads network/*, eks/*
04_vault                            reads data/*, eks/*, bootstrap/*
```
Where lookups live:
- Values **another layer** owns → the root's `data.tf`, passed into child modules as inputs.
- Values a module needs **internally** (`aws_iam_policy_document`, `aws_availability_zones`) → inside the child.
A child module never looks up another layer's resources by itself; that keeps it reusable.

## 4. Secrets

`sensitive = true` only hides a value in plan output. **It is still stored in plain text in the state.**
So secrets never pass through variables or tfvars.

| Secret | Source | In state? |
|---|---|---|
| RDS master password | `manage_master_user_password = true` (RDS → Secrets Manager) | No |
| App DB credentials | Vault dynamic credentials → ESO | No |
| Vault token for `04_vault` | `ephemeral "aws_secretsmanager_secret_version"` (Terraform ≥ 1.10) | No |
| A password Terraform must set | write-only arguments, e.g. `password_wo` (Terraform ≥ 1.11) | No |
| CI access to AWS | GitHub OIDC → IAM role | no keys exist |
| Platform secrets (Grafana, Slack) | Vault KV → ESO | No |

Safety nets: state bucket encrypted, versioned, public access blocked, `prevent_destroy`; `*.auto.tfvars` gitignored;
pre-commit runs `gitleaks` and `trivy config`.

## 5. Versions

- `required_version` is identical in every layer, and CI uses the same Terraform version.
- Providers: `~> major.0` in `versions.tf`; exact builds pinned by the committed `.terraform.lock.hcl`.
- Community modules: **exact** version (`version = "x.y.z"`). Upgrades happen in their own PR.
- Kubernetes version is a variable; CI checks it against the end of standard support.

## 6. Layers and lifecycle

| Layer | Lifecycle | Contents |
|---|---|---|
| `00_bootstrap` | Persistent | State bucket, Budget, GitHub OIDC roles, ECR, ACM, Cognito, Vault KMS key, Loki bucket, CloudTrail |
| `01_network` | Daily | VPC, subnets, NAT instance, S3 gateway endpoint |
| `02_eks` | Daily | EKS, node group, add-ons, access entries, Pod Identity roles (Argo CD bootstrap: next slice) |
| `03_data` | Daily | RDS PostgreSQL |
| `04_vault` | Daily | Vault configuration (Terraform Vault provider) |

Apply in order `00 → 04`; destroy in reverse `04 → 01` (`00_bootstrap` is never destroyed).
Environments (dev/prod) are Kubernetes namespaces managed by Argo CD, not separate infrastructure folders.

## 7. Before every commit

```bash
terraform fmt -recursive
pre-commit run --all-files     # fmt, validate, tflint, trivy config, gitleaks, terraform-docs
```
